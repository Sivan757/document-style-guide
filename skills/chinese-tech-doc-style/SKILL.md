# 中文技术文档写作规范

本技能把阮一峰的《中文技术文档的写作规范》（https://github.com/ruanyf/document-style-guide，公共领域）转成可执行规则。规则来自原文，标记为「补充」的条目是落地经验，不是原文要求。

## 使用顺序

1. 先确认文档类型与读者：README、手册、API 参考、发布说明的详略和结构不同。
2. 写作或修改时，先满足下面「高频错误」一节，再处理章节结构。
3. 交付前跑 `scripts/check_style.py` 扫描，逐条人工复核，误报可以忽略。
4. 仓库已有排版约定时跟随仓库，并在回复里说明取舍。
5. 需要原文措辞、完整示例或边界情况时，读 `references/` 下对应小节。

## 高频错误

这 12 条覆盖真实文档里绝大多数问题。写作时逐条对照，修改时优先修这些。

| 错误 | 正确 |
| --- | --- |
| 本文介绍如何快速启动Windows系统。 | 本文介绍如何快速启动 Windows 系统。 |
| 他的电脑是 MacBook Air 。 | 他的电脑是 MacBook Air。 |
| 价格是１０００元。 | 价格是 1000 元。 |
| 公司有 Google, Facebook, 腾讯。 | 公司有 Google、Facebook、腾讯。 |
| 我们准备了香蕉、苹果、梨…等水果。 | 我们准备了香蕉、苹果、梨等水果。 |
| 太棒了！！！ | 太棒了。 |
| 请确认没有接通装置的电源。 | 请确认装置的电源已关闭。 |
| 没有删除权限的用户，不能删除此文件。 | 用户必须拥有删除权限，才能删除此文件。 |
| 假如此软件尚未被安装 | 假如尚未安装这个软件 |
| 这是唯二的快速启动的方法。 | 这是仅有的两种快速启动的方法。 |
| 请参照第 1.3 节（见第 26 页。） | 请参照第 1.3 节（见第 26 页）。 |
| 名词解释.md | glossary.md |

## 一、中英混排与空格

1. 全角中文字符与半角英文字符之间，加一个半角空格。
   `错误：本文介绍如何快速启动Windows系统。` / `正确：本文介绍如何快速启动 Windows 系统。`
2. 中文与半角阿拉伯数字之间可有可无空格，但全文必须统一，不能两种风格混杂。半角百分号视同数字。
3. 单位不翻译时，数字与单位符号之间留出空隙：`16 GB`、`1 h = 60 min = 3,600 s`。
4. 半角字符与全角标点之间不留空格：`MacBook Air。`，不是 `MacBook Air 。`。
5. 补充：Markdown 行内代码、链接地址、代码块内不套用空格规则；判定时看渲染后的中文正文。

## 二、标点符号

1. 中文语句一律用全角标点；整句为英文时用半角标点。
2. 句号、问号、叹号、逗号、顿号、分号、冒号不得出现在一行之首。
3. 点号（句号、逗号、顿号、分号、冒号）不得出现在标题末尾；引号、括号、破折号、省略号、书名号、叹号、问号可以。
4. 句末用括号加注时，句号在括号之外。
5. 并列词用顿号分隔，不用逗号，并列项是英文也一样；并列项的最后一项用「和」连接读起来更顺。
6. 引号用全角双引号 `“ ”`，内层用单引号 `‘ ’`；圆括号用全角 `（）`，括号前后不加空格。
7. 表示时间用半角冒号：`早上 8:00`；解释说明用全角冒号。
8. 省略号用 `⋯⋯`（两个字位置、六个点），不用 `。。。` 或 `...`；省略号不与「等」同时出现。
9. 少用感叹号，不复用 `！！` 或 `!!!`。
10. 破折号占两个汉字位置，写 `————`；若只占一个汉字位置，前后各留一个半角空格。
11. 连接号：两个名词复合、图表编号用半角 `-`（`氧化-还原反应`、`图 1-1`）；数值范围用 `～` 或 `—`，占一个全角位置，也可以用「至」。
12. 避免「一逗到底」，整段只有结尾一个句号。

## 三、数值、单位与变化

1. 阿拉伯数字只用半角，不用全角。
2. 四位以上数值加千分号 `,`；四位数可选，如 `1000` 与 `1,000` 都可接受。
3. 货币写阿拉伯数字，数字前给符号或数字后给中文名称：`$1,000`、`1,000 美元`。
4. 数值范围用 `～` 或 `—` 连接，带单位或百分号时两端都要写：`132 kg～234 kg`、`67%～89%`。
5. 「增加了」表增量，「增加到」表定量；减少同理用「降低了」「降低到」。
6. 不写「降低 N 倍」「减少 N 倍」，改写百分数：降低一倍等于归零，语义不成立。

## 四、段落与句子

1. 一个段落只讲一个主题，中心句放段首，其余句子为中心句服务。
2. 段落不超过七行，最佳不超过四行；段落之间空一行；段首不留空白字符。
3. 句子尽量短：不含标点的单句或在逗号处切分的构件控制在 20 字以内，20～29 字可接受，30～39 字须语义明确，超过 40 字不接受。逗号长句总长不超过 100 字或正文三行。
4. 多用简单句和并列句，少用复合句；优先肯定句，避免双重否定。
5. 用主动语态，不用被动语态；不用非正式语气；不写冷僻词、生造词、文言词。
6. 区分「的、地、得」：形容词＋的＋名词，副词＋地＋动词，动词＋得＋补语。
7. 代词（其、该、此、这）必须只有一个明确指向；名词前不堆形容词。

## 五、标题与结构

1. 标题最多四级：一级是文章标题，二级是主要部分，三级是小节，四级是某一方面。
2. 一级标题下不能直接出现三级标题，层级不得跳级。
3. 避免孤立编号：同级标题只有一个时，合并到上一级。
4. 下级标题不重复上级标题的名字。
5. 慎用四级标题。三级标题下有并列内容时，改用项目列表或 `**（1）A**` 这样的加粗编号。
6. 软件手册的推荐结构：简介、快速上手、入门篇（环境准备、安装、设置）、进阶篇、API、FAQ、附录（Glossary、Recipes、Troubleshooting、ChangeLog、Feedback）。方括号内标注 [必备]、[可选]。

## 六、文件名与引用

1. 文件名不含空格，只用半角字符，因此不用中文；建议全小写；多词之间用连字符：`advanced-usage.md`，不是 `TroubleShooting.md`、`advanced_usage.md`。
2. 醒目文件才用大写：`README`、`LICENSE`。
3. 引用第三方内容注明出处；整篇转载在开头显著位置写明作者、出处并链接原文；用外部图片在图片下方或文末标明来源。
4. 英文缩写首次出现给中文标注：`IOC（International Olympic Committee，国际奥林匹克委员会）`，此后直接用缩写。
5. 英文书名、电影名改用书名号《》；中文语境不用英文省略号 `...`；专有名词每个实词首字母大写，普通名词短语不大写。

## 交付前自检

- [ ] 中文与英文之间、数字与单位之间的空格是否一致
- [ ] 是否有半角标点混进中文句子，是否有标点起行
- [ ] 是否还有全角数字、未加千分号的四位以上数字
- [ ] 是否有超过 40 字的句子、超过七行的段落
- [ ] 标题是否跳级、是否孤立、是否重名、是否以点号结尾
- [ ] 文件名是否全半角小写连字符
- [ ] 引用与图片来源是否标注

## 脚本

`scripts/check_style.py` 检查可以机械判定的部分：全角数字、中文与英文紧贴、半角标点混排、感叹号连用、非标准省略号、标题跳级与点号结尾、文件名规范、`降低 N 倍`、五位以上数字缺千分号，以及中文与数字的空格风格是否前后一致。

```bash
python3 scripts/check_style.py docs/            # 扫描目录
python3 scripts/check_style.py README.md --json # 机器可读输出
```

脚本只覆盖机械规则；句子长度、段落长度、语气与语态仍需人工判断。
